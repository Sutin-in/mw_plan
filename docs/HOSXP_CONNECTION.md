# การเชื่อมต่อ HOSxP (สำหรับฝ่าย IT) — HOSxP connection guide

ระบบนี้ **อ่านอย่างเดียว** จากฐานข้อมูล HOSxP ไม่เขียน ไม่แก้ไข HOSxP (ADR-007)
The system only **reads** HOSxP; it never writes to it.

## ข้อมูลที่ระบบต้องอ่าน (Operations)

| # | ข้อมูล | ใช้ทำอะไร |
|---|---|---|
| 1 | หัว PR ตามเลขที่ PR: เลขที่, วันที่, **ปีงบประมาณ**, หน่วยงาน, ประเภทงบ, ชื่องบ, ผู้ขอ, **ยอดรวม**, สถานะ | ตรวจก่อนออก PPR |
| 2 | รายการใน PR ทุกบรรทัด: รหัสสินค้า, จำนวน, หน่วย, ราคา/หน่วย, มูลค่ารวม | ตรวจกับแผน |
| 3 | รายชื่อหน่วยงาน | master sync |
| 4 | รายการสินค้า/พัสดุ | master sync |
| 5 | ประเภทงบ (แหล่งเงิน) | master sync |
| 6 | ชื่องบ / หมวดงบ (และหมวดแม่ถ้ามี) | master sync |
| 7 | ผู้ใช้ตามชื่อผู้ใช้: รหัสผู้ใช้, ชื่อผู้ใช้, **ค่า MD5 ของรหัสผ่าน** (`password_hash`), ชื่อ, หน่วยงาน, ใช้งานอยู่หรือไม่ (`get_login_user`) | login (D-25) |
| 8 | ข้อมูลผู้ใช้ตามรหัสผู้ใช้: รหัส, ชื่อผู้ใช้, ชื่อ, หน่วยงาน, ใช้งานอยู่หรือไม่ (`get_user_profile`) | login (D-25) |
| 9 | *(ไม่บังคับ)* การเบิกจากคลังกลางให้หน่วยงานและการรับคืน ตามช่วงวันที่: เลขที่รายการ, วันที่, หน่วยงาน, รหัสสินค้า, จำนวน (บวกเสมอ), ประเภทรายการของ HOSxP (`[stock_movement]`) | แสดงในรายงานการใช้แผนกลางเท่านั้น (D-39) |

## วิธีที่แนะนำ: ชุด interface views (ง่ายที่สุด)

ใช้ชุดไฟล์ใน `docs/hosxp_interface/`: IT สร้าง view 7 ตัวใน schema `ppr_interface` ตามแบบ
(`ppr_interface_views.sql`, ความหมายทุกคอลัมน์อยู่ใน `README.md`) แล้วใช้ไฟล์ query สำเร็จรูป
`hosxp_queries.views.toml` ได้ทันที ไม่ต้องเขียน query เอง และบัญชี `ppr_readonly` ได้สิทธิ์
เฉพาะ view เหล่านี้ (ไม่ต้อง `GRANT SELECT ON ALL TABLES` ในขั้นที่ 1 ด้านล่าง)

## ขั้นตอน

**1. สร้างบัญชีฐานข้อมูลแบบอ่านอย่างเดียว** (ทำโดย DBA/IT บนเซิร์ฟเวอร์ HOSxP; ถ้ามี replica / standby ให้ใช้ตัวนั้น เพื่อไม่กระทบระบบหลัก)

**PostgreSQL** (HOSxP ของโรงพยาบาลนี้): รันด้วยผู้ใช้ที่เป็นเจ้าของฐานข้อมูลหรือ superuser
```sql
CREATE ROLE ppr_readonly LOGIN PASSWORD '<รหัสผ่านยาว ๆ>';
ALTER ROLE ppr_readonly SET default_transaction_read_only = on;
GRANT CONNECT ON DATABASE <ชื่อฐานข้อมูล HOSxP> TO ppr_readonly;
-- ทำซ้ำสำหรับทุก schema ที่ HOSxP ใช้ (ปกติคือ public)
GRANT USAGE ON SCHEMA public TO ppr_readonly;
GRANT SELECT ON ALL TABLES IN SCHEMA public TO ppr_readonly;
```
และเพิ่มใน `pg_hba.conf` ให้เข้าได้เฉพาะจาก IP เครื่องที่รันระบบ PPR เช่น
`host  <ชื่อฐานข้อมูล HOSxP>  ppr_readonly  <IP เครื่อง PPR>/32  scram-sha-256` แล้ว reload PostgreSQL
หลังเขียน query เสร็จ ควรจำกัด `GRANT SELECT` ให้เหลือเฉพาะตารางที่ใช้จริง (least privilege)

MySQL / MariaDB (ถ้าเป็นระบบอื่น):
```sql
CREATE USER 'ppr_readonly'@'<IP เครื่อง PPR>' IDENTIFIED BY '<รหัสผ่านยาว ๆ>';
GRANT SELECT ON <ชื่อฐานข้อมูล HOSxP>.* TO 'ppr_readonly'@'<IP เครื่อง PPR>';
```

**2. ใส่การเชื่อมต่อใน `.env`** ของเครื่องที่รันระบบ (ไฟล์นี้ไม่ถูก commit):
```
PPR_HOSXP_DATABASE_URL=postgresql+psycopg://ppr_readonly:<รหัสผ่าน>@<host>:5432/<ชื่อฐานข้อมูล>
```
(ถ้ารหัสผ่านมีอักขระพิเศษ เช่น `@ : / #` ต้องเข้ารหัสแบบ URL เช่น `@` → `%40`)

**ถ้าบัญชีผู้ใช้ HOSxP อยู่คนละ server กับข้อมูลคลัง/PR (D-41)** ใส่อีกบรรทัด (บัญชีอ่านอย่างเดียวเช่นกัน):
```
PPR_HOSXP_AUTH_DATABASE_URL=postgresql+psycopg://ppr_readonly:<รหัสผ่าน>@<host login>:5432/<ชื่อฐานข้อมูล>
```
ระบบใช้การเชื่อมต่อนี้เฉพาะ `get_login_user` และ `get_user_profile`; query อื่นทั้งหมดใช้ `PPR_HOSXP_DATABASE_URL`
ถ้าไม่ใส่ ใช้ฐานข้อมูลเดียวเหมือนเดิม

**3. สำรวจโครงสร้างฐานข้อมูล** (อ่านเฉพาะ *ชื่อ* ตารางและคอลัมน์ ไม่อ่านข้อมูลใด ๆ):
```
.venv\Scripts\python -m ppr.cli hosxp-schema --out hosxp_schema.md
```
ตรวจไฟล์ `hosxp_schema.md` แล้วส่งให้ผู้พัฒนา (มีแต่ชื่อตาราง/คอลัมน์ ไม่มีข้อมูลผู้ป่วย)
ถ้า HOSxP ไม่ได้อยู่ใน schema `public` ให้เพิ่ม `--schema <ชื่อ schema>`
ถ้าต้องการจำกัด: `--match pr,purchase,request,stock,budget,item,dep`

**4. ผู้พัฒนาเขียน `hosxp_queries.toml`** จาก `hosxp_queries.example.toml` โดยอ้างอิงโครงสร้างจริง
และเทียบกับหน้าจอ PR จริง (เช่น ปีงบประมาณ, ยอดรวม, ประเภทงบ, ชื่องบ)

**5. ทดสอบกับ PR จริง** แล้วเทียบกับหน้าจอ HOSxP:
```
.venv\Scripts\python -m ppr.cli hosxp-check --pr <เลขที่ PR>
```
ต้องได้ `RESULT: OK`, จำนวนบรรทัดครบ, ยอดรวมหัวตรงกับหน้าจอ, ปีงบประมาณถูกต้อง

**6. ตรวจครบทุกข้อก่อนเปิดใช้** (อ่านอย่างเดียว ผลเป็น PASS / FAIL / OPEN ใช้เป็นหลักฐานใน checklist):
```
.venv\Scripts\python -m ppr.cli hosxp-verify --pr <เลขที่ PR> --out hosxp_verify.md
```
รายละเอียดอยู่ใน `docs/IT_HANDOFF.md` ขั้นที่ 3

**7. เปิดใช้งาน:** ตั้ง `PPR_HOSXP_MODE=sql` ใน `.env`

## ความปลอดภัย
- อ่านอย่างเดียว 3 ชั้น: ตรวจข้อความ query, transaction แบบ READ ONLY, และบัญชีที่มีสิทธิ์ SELECT เท่านั้น
- ถ้า HOSxP ติดต่อไม่ได้ หรือ query ผิด ระบบจะ **ปฏิเสธ** ไม่ใช้ข้อมูลเก่าหรือข้อมูลบางส่วน
- ข้อความ error ไม่แสดงข้อมูลในแถว; รหัสผ่านถูกซ่อนเสมอ

## Login ด้วยบัญชี HOSxP (D-25)
- ผู้บริหารโครงการแจ้งว่า HOSxP เก็บรหัสผ่านเป็นค่า MD5 ตอนนี้ระบบคำนวณ MD5 ของรหัสผ่านที่ผู้ใช้พิมพ์ (UTF-8) แล้วเทียบกับค่าที่อ่านจาก HOSxP แบบไม่สนตัวพิมพ์เล็ก/ใหญ่ และใช้ค่า `active` ตามที่ query ของโรงพยาบาลส่งมา — **ทั้งหมดนี้เป็นการตั้งค่าชั่วคราว ยังไม่ได้ยืนยันกับ HOSxP จริง**
- IT เขียน `[queries.get_login_user]` และ `[queries.get_user_profile]` ใน `hosxp_queries.toml` จากตารางจริง (ระบบไม่เดาชื่อตาราง/คอลัมน์)
- ตรวจ query login ของบัญชีหนึ่งได้โดยไม่ต้องใส่รหัสผ่าน: `python -m ppr.cli hosxp-check --user <ชื่อผู้ใช้>`
  (แสดงว่าพบหรือไม่, ใช้งานอยู่หรือไม่, มีหน่วยงานหรือไม่, ค่ารหัสผ่านเป็นรูปแบบ MD5 หรือไม่ — ไม่แสดงค่ารหัสผ่านหรือชื่อบุคคล)
- D-41: หน่วยงานของผู้ใช้ไม่บังคับ — PPR ใช้หน่วยงานตาม PR ใน HOSxP; ผู้ขอเห็นเฉพาะ PPR ที่ตัวเองสร้าง

**ก่อนเปิดใช้ login จริง ต้องมีหลักฐานจาก HOSxP ของโรงพยาบาลครบ 4 ข้อ** (บันทึกผล ผู้ตรวจ และวันที่):
1. query ใน `hosxp_queries.toml` อ่านตาราง/คอลัมน์ที่ถูกต้อง (ชื่อผู้ใช้, รหัสผู้ใช้, ค่ารหัสผ่าน, ชื่อ, หน่วยงาน, สถานะบัญชี) — ทดสอบกับบัญชีจริง
2. รูปแบบค่ารหัสผ่านที่เก็บ: เป็น MD5 ฐานสิบหก 32 ตัวอักษรตรง ๆ หรือรูปแบบอื่น/มีส่วนเพิ่ม และมี prefix/suffix/ตัวพิมพ์/ช่องว่างหรือไม่
3. การเข้ารหัสตัวอักษรของรหัสผ่านก่อนคำนวณ MD5 — ทดสอบกับบัญชีที่มีรหัสผ่านภาษาไทยอย่างน้อย 1 บัญชี (ถ้าไม่ผ่าน อาจไม่ใช่ UTF-8)
4. ความหมายที่แน่นอนของ "บัญชีใช้งานอยู่/ปิดใช้งาน" ใน HOSxP (รวมบัญชีที่ถูกล็อก หมดอายุ หรือถูกลบ) และ query แปลงเป็น `active` อย่างไร

ถ้าข้อใดไม่ตรงกับที่ระบบทำอยู่ ให้แจ้งทีมพัฒนาเพื่อแก้ระบบ (พร้อมทดสอบ) ก่อนเปิดใช้งาน
- ระบบนี้ไม่เก็บ ไม่บันทึก log และไม่แสดงรหัสผ่านหรือค่า MD5

## ยังไม่รวมในขั้นนี้
- ยอดงบของ HOSxP (ยังไม่ใช้ในฟีเจอร์ปัจจุบัน)

## ยอดเบิก/คืนจากคลังกลาง (ไม่บังคับ, D-39)

- ระบบคลัง การเบิก การคืน และยอดคงคลังเป็นของ HOSxP ระบบนี้**อ่านอย่างเดียว**ขณะเปิดรายงาน
  "การใช้แผนกลาง" ไม่เก็บสำเนา และ**ไม่ลงบัญชีแผน (Plan Ledger)** ไม่ว่ากรณีใด
- เขียนในหมวด `[stock_movement]` ของไฟล์ query (ไม่ใช่ใต้ `[queries]`) พร้อมบันทึกการยืนยัน
  `verified_by`, `verified_on`, `reference` และตาราง `[stock_movement.kind_map]` ที่จับคู่
  ประเภทรายการของ HOSxP กับ `ISSUE` (เบิก) / `RETURN` (คืน) ตามตัวอย่างใน `hosxp_queries.example.toml`
- ถ้าไม่มีหมวดนี้ ยังไม่ได้ยืนยัน หรือ query ผิด รายงานจะแสดง "ยังไม่มีข้อมูล" และส่วนอื่นของระบบทำงานตามปกติ
- รายการที่มีประเภทซึ่งยังไม่ได้จับคู่ ทำให้ยอดของสินค้าและหน่วยงานนั้นแสดง "ยังไม่มีข้อมูล" (ไม่นับเป็นศูนย์)
- สินค้าที่อยู่ในแผนมากกว่าหนึ่งรายการ (แผนกลางหลายแหล่งเงิน หรือมีในแผนหน่วยงาน/แผนซื้อแทนด้วย) จะแสดงยอดเบิกรวมของสินค้าเพียงแถวเดียว ไม่แบ่งและไม่ผูกกับรายการแผนใด
- IT ต้องยืนยันว่า HOSxP บันทึกการรับคืนอย่างไร ถ้ายังไม่กำหนดประเภท `RETURN` ยอดคืนและยอดใช้สุทธิจะแสดง "ยังไม่มีข้อมูล"
- ตรวจสถานะได้จาก `python -m ppr.cli hosxp-check` (บรรทัด `stock movements (optional)`)
