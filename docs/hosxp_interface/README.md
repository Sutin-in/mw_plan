# ชุดเชื่อมต่อ HOSxP สำหรับระบบ PPR (สำหรับฝ่าย IT)

ระบบ PPR อ่านข้อมูล HOSxP **อย่างเดียว** ผ่าน "view" 7 ตัวใน schema `ppr_interface`
ที่ฝ่าย IT สร้างขึ้นในฐานข้อมูล HOSxP ครั้งเดียว ไม่ต้องเขียน API และไม่ต้องเขียน query เอง

| ไฟล์ | ใช้ทำอะไร |
|---|---|
| `ppr_interface_views.sql` | แบบ view ที่ IT เติมชื่อตาราง/คอลัมน์ HOSxP ลงในช่อง `< >` แล้วรัน |
| `hosxp_queries.views.toml` | ไฟล์ query สำเร็จรูปของระบบ PPR ที่อ่านจาก view เหล่านี้ (ไม่ต้องแก้) |
| `README.md` | ความหมายของทุกคอลัมน์ (ไฟล์นี้) |

## ขั้นตอน

1. เปิด `ppr_interface_views.sql` แทนทุกช่อง `< >` ด้วยตาราง/คอลัมน์จริงของ HOSxP ตามความหมายในตารางด้านล่าง
2. รันไฟล์บนฐานข้อมูล HOSxP (หรือ replica) ด้วยผู้ใช้ที่มีสิทธิ์สร้าง view
3. ทดสอบใน pgAdmin เช่น `SELECT * FROM ppr_interface.pr_header WHERE pr_no = '<เลขที่ PR จริง>'` ต้องได้ 1 แถว ตัวเลขตรงกับหน้าจอ HOSxP
4. คัดลอก `hosxp_queries.views.toml` ไปเป็น `hosxp_queries.toml` ที่โฟลเดอร์หลักของระบบ PPR
5. รัน `.venv\Scripts\python -m ppr.cli hosxp-check --pr <เลขที่ PR จริง>` ต้องได้ `RESULT: OK`

ข้อดี: บัญชี `ppr_readonly` เห็นเฉพาะ view 7 ตัวนี้ ไม่เห็นตารางผู้ป่วยหรือตารางอื่นของ HOSxP

## กติการ่วมทุก view

- ชื่อ view และชื่อคอลัมน์ต้องตรงตามแบบทุกตัว
- รหัส (id) ทุกตัวเป็นข้อความ (`text`) และต้องเป็น **รหัสชุดเดียวกัน** ทุกที่ที่อ้างถึงกัน
- จำนวน ราคา มูลค่า ใช้ `numeric` แบบไม่ระบุทศนิยม ห้าม `numeric(18,2)` เพราะจะปัดเศษเอง
- `active` เป็น boolean: จริง = ยังใช้งาน, เท็จ = ยกเลิก/ปิดใช้งาน
- ช่องที่ไม่มีข้อมูลใน HOSxP ใส่ `NULL` ได้ ถ้าตารางด้านล่างเขียนว่า "ไม่บังคับ"

## 1. `pr_header` — หัวใบขอซื้อ (1 แถวต่อ 1 เลขที่ PR)

| คอลัมน์ | ชนิด | บังคับ | ความหมาย | ข้อควรระวัง |
|---|---|---|---|---|
| `pr_id` | text | บังคับ | รหัสภายในของ PR (primary key) | ต้องไม่เปลี่ยนตลอดอายุ PR ใช้ยืนยันว่าเป็นใบเดิม |
| `pr_no` | text | บังคับ | เลขที่ PR ที่ผู้ใช้เห็นและพิมพ์ค้นหา | 1 เลขที่ต้องได้ 1 แถวเท่านั้น |
| `pr_date` | date | ไม่บังคับ | วันที่ของ PR | |
| `fiscal_year` | integer | จำเป็นในทางปฏิบัติ | ปีงบประมาณของ PR เป็น **พ.ศ.** เช่น 2570 | ถ้า HOSxP เก็บ ค.ศ. ให้ + 543; ไม่มีค่า = ออก PPR ไม่ได้ |
| `department_id` | text | จำเป็นในทางปฏิบัติ | หน่วยงานที่ขอซื้อ | ต้องตรงกับ `department.source_id` |
| `fund_source_id` | text | จำเป็นในทางปฏิบัติ | ประเภทงบ/แหล่งเงิน | ต้องตรงกับ `fund_source.source_id` |
| `budget_category_id` | text | ไม่บังคับ | ชื่องบ/หมวดงบ | ต้องตรงกับ `budget_category.source_id` |
| `requester_id` | text | ไม่บังคับ | รหัสผู้ขอซื้อ | |
| `requester_name` | text | ไม่บังคับ | ชื่อผู้ขอซื้อ | ใช้ค้นหาเท่านั้น |
| `total_amount` | numeric | จำเป็นในทางปฏิบัติ | ยอดรวมของ PR ตามหน้าจอ | ต้องเท่ากับผลรวม `pr_item.amount` ทุกบรรทัด (D-17) |
| `native_status` | text | จำเป็นในทางปฏิบัติ | สถานะ PR **ค่าดิบ** ตามที่ HOSxP เก็บ | ห้ามแปลง; ความหมายตั้งภายหลังเมื่อมีหลักฐาน (D-30) |
| `last_modified_at` | timestamp | ไม่บังคับ | วันเวลาที่แก้ PR ล่าสุด | ใส่ `NULL` ได้ถ้าไม่มี |

## 2. `pr_item` — รายการในใบ PR (1 แถวต่อ 1 บรรทัด)

| คอลัมน์ | ชนิด | บังคับ | ความหมาย | ข้อควรระวัง |
|---|---|---|---|---|
| `pr_no` | text | บังคับ | เลขที่ PR ของบรรทัดนี้ | ค่าเดียวกับ `pr_header.pr_no` (ใช้กรอง) |
| `pr_item_id` | text | บังคับ | รหัสบรรทัด | ไม่ซ้ำภายใน PR และไม่เปลี่ยน |
| `item_id` | text | บังคับ | รหัสสินค้า/พัสดุ | ต้องตรงกับ `item.source_id` (ใช้จับคู่กับแผน) |
| `item_code` | text | ไม่บังคับ | รหัสย่อสินค้า | |
| `item_name` | text | ไม่บังคับ | ชื่อสินค้า | |
| `qty` | numeric | บังคับ | จำนวนที่ขอ | ทศนิยมไม่เกิน 4 ตำแหน่ง |
| `unit` | text | ไม่บังคับ | หน่วยนับ | |
| `unit_price` | numeric | บังคับ | ราคาต่อหน่วย | ทศนิยมไม่เกิน 8 ตำแหน่ง |
| `amount` | numeric | บังคับ | มูลค่ารวมของบรรทัด | ทศนิยมไม่เกิน 2 ตำแหน่ง |

## 3–6. ข้อมูลหลัก

| view | คอลัมน์ (บังคับทุกตัว เว้นที่ระบุ) | ความหมาย |
|---|---|---|
| `department` | `source_id`, `code`, `name`, `active` | หน่วยงาน |
| `item` | `source_id`, `code`, `name`, `unit`, `active` | สินค้า/พัสดุ |
| `fund_source` | `source_id`, `code`, `name`, `active` | ประเภทงบ (แหล่งเงิน) |
| `budget_category` | `source_id`, `code`, `name`, `parent_source_id` (ไม่บังคับ), `active` | ชื่องบ/หมวดงบ มีหมวดแม่ได้ |

`source_id` = รหัสหลักที่ไม่เปลี่ยน, `code` = รหัสย่อที่ผู้ใช้เห็น, `name` = ชื่อ

## 7. `app_user` — ผู้ใช้สำหรับ login (D-25)

| คอลัมน์ | ชนิด | บังคับ | ความหมาย | ข้อควรระวัง |
|---|---|---|---|---|
| `source_id` | text | บังคับ | รหัสผู้ใช้ที่ไม่เปลี่ยน | |
| `username` | text | บังคับ | ชื่อผู้ใช้ที่พิมพ์ตอน login HOSxP | |
| `display_name` | text | ไม่บังคับ | ชื่อ-สกุล | |
| `department_id` | text | ไม่บังคับ | หน่วยงานของผู้ใช้ | ต้องตรงกับ `department.source_id` |
| `password_hash` | text | บังคับ | ค่ารหัสผ่านที่ HOSxP เก็บ (MD5) | ส่งตามที่เก็บจริง ไม่แปลง; ระบบใช้เทียบเท่านั้น ไม่เก็บ ไม่แสดง |
| `active` | boolean | ไม่บังคับ | บัญชียังใช้งานได้ | บัญชีที่ล็อก/หมดอายุ/ลบ ต้องเป็นเท็จ |

การ login ด้วยบัญชี HOSxP จะเปิดใช้จริงเมื่อมีหลักฐานครบตามแบบฟอร์มหลักฐาน ข้อ 8–11 เท่านั้น

## สิ่งที่ยังไม่อยู่ในชุดนี้

ยอดงบของ HOSxP และการเบิกจากคลังกลาง จะเพิ่มเป็น view ภายหลัง (Wave 7/9)
